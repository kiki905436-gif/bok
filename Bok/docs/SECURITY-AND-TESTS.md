# Bok 安全边界与测试计划

## 主要威胁与处理

| 威胁 | 处理 |
|---|---|
| 路径穿越 | 所有路径必须是 Vault 相对路径，拒绝绝对路径和 `..` |
| 符号链接逃逸 | 读写路径逐段拒绝符号链接，并验证真实父目录仍在 Vault 内 |
| 运行时数据泄露 | 文档读取只允许索引范围内的 Markdown，拒绝 `.bok`、私有目录和非 Markdown 文件 |
| 备份路径穿越 | 备份 ID 使用严格格式校验，不能拼接任意本机路径 |
| 并发静默覆盖 | 编辑、移动和回收必须携带读取时的内容哈希 |
| 崩溃产生半文件 | 同目录临时文件、`fsync`、原子替换 |
| AI 改写重要记忆 | 类型、目标卡、敏感性和冲突任一命中即进入待处理 |
| 云端静默外发 | Local Only 拒绝所有非 loopback URL；关闭后仍需逐请求 consent |
| API 被本机网页滥用 | loopback、Bearer Token、无 CORS、CSP、限流和 1 MiB 上限 |
| UI 暴露 API Token / CSRF 写入 | 同源服务端 bridge 代持 Token；POST 必须有匹配 Host 的 Origin/Referer 与同源 Fetch 证明；Token 轮换不开放给浏览器 |
| 浏览器选择任意本机目录 | Personal Core 路径配置不开放给浏览器 bridge，只允许受信本机 API/CLI并要求显式确认 |
| 重复点击 | 幂等键绑定请求指纹 |
| Prompt Injection | 模型系统指令声明材料不可信；模型输出再做类型、路径和敏感校验 |
| 对话轮次丢失 | 先原子写 Conversation Ledger，再投递后台捕获；启动和显式 reconcile 可补投 |
| 轮次重放或篡改 | `(conversation_id, turn_id)` 生成稳定事件 ID；相同内容幂等，不同内容/策略返回冲突 |
| 引用材料污染个人模型 | 外部网页、文档、附件与转发材料必须标记 `external_content`，入口禁止进入个人分析 |
| 用户要求不记忆却留存正文 | `do_not_remember` 事件不写正文；公开接口不返回正文、指纹或云端授权标记 |
| 模型离线造成原文无限滞留 | Session Buffer 保留期到期时同步 discard 未处理捕获正文，只留审计元数据 |
| 大队列反复重写与单点损坏 | 对话事件和捕获记录使用一条一文件分片；旧 `capture-queue.json` 启动时安全迁移并清空重复原文 |
| 私人画像混入共享/公开 Vault | Personal Core 必须在项目 Vault 与 Git 仓库之外；未配置时禁用，不创建 `08-Person` |
| 手改 Markdown 伪造已确认画像 | Claim 读取校验状态、用户确认、来源、时间、ID/文件名、类型和范围；任何不一致失败关闭 |
| Personal Core 符号链接逃逸 | 根、Claims、`.bok` 和 Claim 文件拒绝符号链接；陌生非空目录拒绝接管 |
| 替代关系写一半 | 后继先落原子文件；启动按 `supersedes` 修复旧 Claim 反向链接；健康检查报告断链与不对称链 |
| 版本写一半 | journal 使用 pending / committed / aborted；启动对当前内容 hash 收敛状态，不猜测写入结果 |
| 错误画像被再次生成 | rejected、精确重复和被纠正的 `statement_history` 建立重建守卫 |
| 单次行为被过度解读 | 单次行为只形成 observation；至少跨 3 次会话和 2 个场景才形成未确认 hypothesis，重要判断仍需用户确认 |
| 用户原句被冒充个人理解 | 没有结构化模型信号时不生成语义观察；第三人称抽象、推断依据和稳定 concept key 必填，近似照抄与临时命令全局化失败关闭 |
| 错误理解在版本/备份/运行态中残留 | “彻底忘记”使用事务 staging 清除 Claim、派生学习记录、版本、命中备份、来源正文和关联幂等响应；已提交项目知识卡只返回待复核路径，不越权静默删除；中断后回滚或完成 |
| Agent 在请求体冒充其他客户端 | 独立 Agent token 绑定 agent ID 与范围；服务端覆盖请求体身份，凭证可撤销且磁盘只保存哈希 |
| 敏感日志 | activity 只记路径、版本和哈希，不保存正文或 API Key |
| 备份投毒 | ZIP 路径和 Markdown 扩展校验、逐文件 SHA-256、恢复前安全备份 |
| 私人备份混入共享库 | Personal Core 使用独立备份目录和清单；恢复要求精确 Core 名，知识库备份与私人备份互不替代 |

## 必须持续通过

- 非 loopback 绑定拒绝。
- 路径穿越、未授权目录和符号链接写入拒绝。
- 过期哈希写入返回冲突。
- 原子写入、版本和回滚恢复原内容。
- 重要编辑、移动、删除和回滚需要明确确认。
- 普通高置信记忆自动提交，重要和冲突记忆保持 pending。
- 捕获返回不包含原始材料，模型离线仍保留队列。
- 对话收据先于下游队列落盘，失败可补投；重复轮次不重复捕获，篡改返回冲突。
- 外部材料、临时会话和不记忆策略不进入长期分析；到期正文从事件和未处理捕获同时移除。
- Token 预算不超限，来源稳定可引用。
- Local Only 即使收到 cloud consent 也拒绝外网。
- API 无 Token 返回 401；幂等重复不产生第二份文件。
- UI bridge 不向浏览器返回 Token、拒绝跨来源写入，并保持 API 幂等语义。
- 备份哈希通过并能在安全备份后恢复。
- MCP 同时支持最新发现方式和旧版 initialize 客户端。
- MCP 自动观察成功回执不返回正文、事件 ID、capture ID 或内容哈希；完整本地收据仍可从认证状态接口取得。
- 普通捕获可按 10～20 条或空闲窗口批量分析；测试确认每条 capture 独立完成、短队列不丢失，模型漏项时只补跑缺失项。
- Personal Core 未配置时安全禁用，项目 Vault 不产生个人画像目录。
- Personal Claim 的确认、纠正、拒绝、替代、解释、回滚、范围过滤和最小上下文持续通过。
- 损坏、伪造、符号链接、替代链中断和 version journal 中断均失败关闭或可恢复。
- 浏览器 bridge 不允许选择 Personal Core 路径；健康响应不暴露绝对路径。
- Observation 幂等、敏感内容无正文收据、跨会话/场景门槛、Outcome/影响和重要清理保护持续通过。
- 无结构化解释时不复制用户原句；原句近似、无推断依据、无 concept key 和临时指令全局化均拒绝落盘。
- 彻底忘记需要独立确认，并清除派生记录、版本、命中备份、来源正文和关联幂等缓存；已提交项目知识卡明确列为待复核，中断事务可确定性恢复。
- Agent 凭证哈希、范围、撤销和请求体身份防冒充持续通过。
- 知识库与 Personal Core 双备份分别创建、校验和恢复前安全快照持续通过。

## 发布前补充验收

- 真实 macOS/Windows 新机启动。
- 磁盘满、只读目录、异常退出和断电注入。
- Bok 与 Obsidian 同时编辑同一文件。
- 1K、10K、100K Markdown 的启动、搜索、内存和增量索引预算。
- Provider 不存在、冷启动、超时、无效 JSON、模型切换和长队列。自动测试使用模拟 Provider，不启动或调用用户的本地模型。
- 云端 Provider 只用脱敏测试 Vault 验证，不使用私人知识库。
- UI 已完成真实 Chrome 桌面/390px、工作台、关于我、搜索、编辑、双备份和关键键盘入口回归；发布前继续补完整 WCAG 辅助技术、真实 Windows 和长期运行验收。

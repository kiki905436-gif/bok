# Bok 丝滑体验契约

## 默认行为

- 不要求用户先分类、命名、选目录或写标签。
- 对话收据、捕获与随手记先本地保存，模型处理不占用前台等待时间。
- 聊天客户端或工作区规则为每个用户原生回合调用 `conversations/observe`，不依赖“之前、记住、知识库”等临时关键词触发。
- “本次不记忆”和“仅本次会话”在发送入口生效，不等后台模型判断。
- 普通高置信内容自动整理，完成后只提供轻提示和撤销。
- 重要内容进入“需要关注”，不弹窗、不抢焦点、不阻断当前任务。
- 显式个人主张先进入 `explicit`，确认前不影响回答；“确认内容”和“允许 Agent 使用”是两个独立动作，确认后默认仍为私人。纠正或拒绝后下一轮立即停止旧判断。
- 单次行为只形成 observation；跨会话/场景形成的 hypothesis 仍在确认前不影响回答。
- 模型离线时显示“已安全排队”，而不是保存失败。
- 重复点击不会重复创建，客户端为写操作生成 `Idempotency-Key`。

## 反馈层级

1. **完全安静**：读取、索引、关键词检索、无变化去重。
2. **轻提示**：已保存随手记、已自动整理、已创建备份，均可查看活动或撤销。
3. **需要关注**：重要记忆、冲突、敏感、低置信、模型长期不可用。
4. **必须明确授权**：修改/删除重要记忆、把已确认个人记忆开放给 Agent、云端发送、备份恢复、凭证设置。

Personal Core 首次路径选择、个人身份/授权规则确认、Claim 回滚、清理重要记忆和 Personal Core 恢复同样属于“必须明确授权”；路径选择不开放给普通浏览器 bridge，恢复前自动创建独立安全备份。

## 性能预算

- 随手记与 capture API 的前台路径不等待模型。
- 对话前台路径只做本地分片写入与队列投递；模型不可用不影响发送和回复。
- 搜索默认 6 条以内、2,500 Token 以内，并优先展示不同来源；日常使用默认快速范围，用户选择“搜索全部”时再纳入归档、基准和低频工程资料。
- 写入后不在前台同步重建全库索引，只标记派生索引失效。
- 第一次本地模型冷启动允许较慢，但状态必须是“后台处理中”。
- UI 每次只拉取当前需要的列表，不下载整个 Vault。
- 个人上下文默认最多 6 条、1,500 Token；Claim Markdown 只做可自动失效的进程内缓存，不生成第二份持久化画像。

## 文案建议

- `已记下`，而不是“文件写入成功”。
- `正在后台整理`，而不是“等待模型推理”。
- `已整理 2 条 · 可撤销`，而不是逐条确认。
- `1 条重要变化待你有空时查看`，而不是强制弹窗。
- `本地模型暂不可用，内容已安全排队`，而不是报错丢失。

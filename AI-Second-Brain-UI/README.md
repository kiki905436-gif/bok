# Boujoy知识库本地预览

> 这是知识库根目录下的本地 UI。原有浏览、检索、关系和健康页保持只读；新增 Bok 工作台通过版本化同源接口执行明确的记忆、编辑和备份操作。macOS 可双击桌面的 `Boujoy知识库.app`，Windows 可双击根目录的 `打开知识库预览.cmd`。
>
> 产品化目标名：**Bok**。Bok 在本项目中只指 Second Brain 知识库产品，不指 Boujoy Harness；当前 App、代码和启动入口尚未执行品牌迁移。

## 一句话结论

这是 Boujoy知识库的 macOS / Windows 双平台本地工作台。它启动后直接读取当前 Vault，不创建第二份知识库，不接外部 API，也不使用数据库；原有浏览与检索保持只读，Bok 工作台通过同源 bridge 调用独立记忆内核，浏览器不接触 Token。

## 适用场景

- 一级入口只保留“今天、项目、知识、我的记忆”，按当前工作和稳定知识组织使用路径。
- 在“知识”中按业务主题聚合导入记录；原始 Markdown 保留为可追溯来源，不与结论层混为一谈。
- 在系统层的“关系探索”中用可缩放、可平移的动态节点查看真实引用，点击直接打开原始 Markdown。
- 从 Dashboard 生成“知识 → 文案 → 动画 / 成片”的只读生产管线。
- 在健康中心查看索引、记忆候选、Skill 同步、制作环境和清理候选。
- 在阅读器中查看表格、任务、代码与本地素材，并复制路径或生成给 Codex 的续接指令。
- 首页当前工作由 `00-System/Active-Context.md` 的 `focus_path` 指向项目卡；下一步行动读取该项目卡，避免系统维护待办覆盖真实项目进度。
- `Asset-Index.md` 已登记视频时才在“今天”出现视频区域，没有数据时不展示空模块。
- 在健康中心对清理报告候选执行二次确认后逐项移入系统废纸篓，并核验原路径确实不存在；报告已过期但文件本来就不在时也会明确记为“已不存在”，不会假报失败。
- 让 Codex 与 WorkBuddy 直接共用同一个本地知识库。
- 在 Agent 更新 Markdown 后，无需生成副本即可看到最新内容。
- 在“系统”中按需打开记忆搜索、受保护候选、随手记、活动/撤销、设置和双备份；普通理解安静形成，不占据一级导航。
- 通过首页、工作台按钮或 `Command/Ctrl + Shift + N` 打开真实独立随手记小窗；断连时保留草稿并允许重试，不静默退回页面内弹层。
- 在“我的记忆”查看自动形成的多维理解、少量受保护事项、观察证据、结果、影响、权限和清理建议。

## 关键决策

- Markdown 始终是唯一数据源。
- 浏览、搜索与健康信息只读，不承担写回、分类和保存判断；删除与清理只在用户主动二次确认后移入系统废纸篓。Bok 工作台写入全部走独立内核的版本、幂等和重要确认规则。
- 不引入外部依赖、外部 API、数据库或常驻云服务；本机同源 bridge 只转发到按需启动的 Bok 产品层，不复制业务逻辑。
- 本地网页应用根据自身所在位置找到 Vault，并在窗口打开期间自动检测文件变化。
- 预览层按标题与正文指纹折叠完全相同的模板副本；不删除、不合并原始 Markdown。
- 搜索会读取知识卡“相关标签”、frontmatter 中的 `tags` / `aliases` / `keywords`，并把 `Hot-Index.md` 与 `Memory-Index.md` 的“触发”字段作为目标卡片别名。
- 多个搜索词采用无顺序的全部命中，并优先展示标题、别名和标签命中的卡片。
- 视觉采用安静的研究工作台：深色导航、暖灰工作区、宋体标题与 Avenir/苹方正文。默认隐藏右侧检查器，只有选中具体记录时才展开；空分类、空视频和空生产管线不占据主界面，系统操作集中到二级入口。
- macOS 默认复用同一个 `127.0.0.1:8765` 本地服务；端口被其他程序占用时才使用随机端口。

## 打开方式

macOS：

1. 双击桌面的 `Boujoy知识库.app`；也可双击根目录的 `打开知识库预览.command`。
2. 独立 Chrome 应用窗口会按启动器所在位置读取同一个 Vault。
3. 首次复制到新 Mac，或需要重建桌面 App 时，双击本目录的 `install-macos-app.command`；安装器会先校验 App，再安全替换并创建桌面入口。

Windows：

1. 双击根目录的 `打开知识库预览.cmd`，或本目录的 `open-preview.cmd`。
2. Windows 原有入口和原生 Tkinter 备用端继续保留。

- 默认通过本机 Python 启动仅绑定 `127.0.0.1` 的临时预览服务，再以 Chrome/Edge 独立窗口显示；Bok bridge 只有首次调用时才按需启动，停止请求 10 分钟后预览服务自动退出。
- macOS 启动器会等待服务握手；启动失败、端口不可用或 Python 缺失时会显示错误与日志路径。
- 重复双击会复用同一 Vault、同一服务和同一 PID；每次启动拥有独立日志，不再依赖易出错的 AppleScript `path to me` 解析。
- Windows 找不到 Python 时，`.cmd` 启动器会先明确说明完整功能所需依赖；用户确认后才通过系统 `winget` 安装 Python 3.12，拒绝或安装失败则进入仅浏览兼容模式。macOS 找不到 Python 时会显示明确错误和日志位置。
- `desktop_app.pyw` 保留为原生 Tkinter 备用入口，并同步使用完全重复内容折叠规则。
- `open-browser-preview.cmd` 是普通浏览器备用入口。
- 如果把本 UI 文件夹单独移动到其他位置，兼容版会要求重新选择知识库，避免误读桌面或其他目录。

## 自动更新

应用窗口每 5 秒检查一次 Markdown 文件的修改时间和大小。

- Codex 或 WorkBuddy 保存 Markdown 后，打开中的应用会自动刷新。
- 新增、修改、删除文件都会触发更新。
- 重新打开应用后会直接读取知识库，不需要再次授权目录。

## 数据边界

- Markdown 是唯一数据源。
- 原有页面默认只读；健康中心提供经过二次确认、仅针对清理报告候选的系统废纸篓操作。Bok 写入口统一走 `/api/bok/v1/...` 同源 bridge、幂等键、版本和重要记忆确认。
- 预览枚举不上传文件、不发送外部网络请求；只使用 `127.0.0.1` 在本机窗口、预览服务与 Bok 内核之间传递内容。云端 Provider 仍受 Bok 的 Local Only 与逐请求授权控制。
- 本地素材接口限制在 Vault 内，支持 `HEAD` 与单段 Range；Finder 定位只接受同源 `POST` 请求并拒绝路径越界。
- 不读取 `.git`、`.bok`、`99-Logs`、依赖和构建目录；预览工程自身只把 `README.md` 作为项目卡展示。

## 产品审计结论

当前版本已经适合本机日常使用：启动失败可见、超大文件先轻量展示再按需读取、重复模板会折叠、卡片按 24 条渐进加载，搜索、阅读器、生产管线、健康中心、真实关系图、移动宽度布局和 Markdown 自动刷新均保留；Bok 工作台与“我的记忆”已经接入同源内核。2026-08-30 的 32 项产品契约，以及真实 Chrome 对 9 个页面、6 个记忆标签、5 个个人记忆标签在 390px、768px、1440px 三档的回归均通过。

本轮已经完成：

0. **信息架构收敛**：一级入口只保留今天、项目、知识、我的记忆；系统能力降级为二级入口，空类型按数据条件隐藏，导入来源按业务主题形成集合。
1. **阅读器增强**：Markdown 内链、表格、任务、图片、音视频、代码复制、复制路径、Finder 定位和给 Codex 的续接指令。
2. **真实知识关系**：优先使用 Markdown 内链、`related` 与 `derived_from` 连边，标签只为孤立节点补边；图谱采用按关联度调整节点大小的力导向布局，支持拖拽平移、滚轮/按钮缩放、悬停高亮和点击打开原卡。
3. **健康中心**：只读汇总索引、记忆候选、制作环境、Skill 同步与清理候选；只有用户主动二次确认后才逐项移入系统废纸篓，完成后再次检查原路径并报告残留。
4. **内容生产管线**：从 Dashboard 读取主题、知识、文案、动画 / 成片和当前状态，已登记文件可直接打开。
5. **启动可靠性**：固定端口优先、同服务复用、首次扫描后再报就绪、独立日志、启动握手、跨站与路径越界防护。
6. **一键 Doctor 与产品回归**：`tools/boujoy-doctor.ps1` 只读检查核心入口、当前工作、索引、Skill SHA、Git hook、PowerShell 语法、桌面 App、Madem 基础能力、历史路径和卡片字段覆盖率；`tests/run-product-tests.ps1` 验证接口、安全边界和真实浏览器体验。
7. **Bok 记忆工作台**：今天、语义搜索、受保护候选、真实独立随手记小窗、活动/撤销、设置、版本编辑和知识库/Personal Core 双备份。
8. **关于我**：低风险理解安静学习；画像、受保护事项、观察证据、Outcome、影响、时间线、权限与垃圾记忆清理候选可视化，错误理解可经不可撤销确认后彻底忘记。

下一阶段按收益排序：

1. **首次上手**：加入原生文件夹选择器、三分钟引导、示例任务和“今天先做什么”，减少新用户理解成本。
2. **商品化安装**：提供版本号、升级说明、授权边界、诊断导出与可复现安装包。
3. **知识质量**：Doctor v2 已按项目、知识、内容和提示词分别检查，直接维护的核心卡字段当前完整；旧文档缺少类型或更新时间时由 schema-on-read 派生，不批量污染原文。
4. **历史项目迁移**：只在重新使用对应项目时，把 Windows 绝对路径逐个改成相对路径并回归。
5. **依赖维护窗口**：Madem 锁定版本保证现有渲染可复现；升级依赖时使用独立分支并跑完整视频回归。

自动化边界保持不变：机器适合自动做索引一致性、断链、重复和环境检查；内容是否值得保存、卡片如何合并、旧判断是否废弃，仍应由 Codex 做语义判断，避免把知识库自动化成资料堆。
